Plataforma Palenke - Documentacion Tecnica MVP

Version 1.0 | Fecha: 2026-05-04 | Estado: Base tecnica para MVP (Fase 1)

1) Objetivo

Este documento describe como funciona la plataforma Palenke en su estado MVP: arquitectura real, modulos principales, reglas de seguridad territorial digital, flujo documental restringido y operacion base.

2) Resumen de la plataforma

  • Infraestructura digital para gestion de informacion territorial y gobernanza.
  • Control de acceso por rol y por nivel de sensibilidad.
  • Conexion entre biblioteca, memoria, estadisticas y geoportal.
  • Soporte a operacion editorial y administrativa en un mismo portal.

3) Arquitectura MVP

Stack
  • Next.js App Router + React + TypeScript
  • Tailwind CSS v4
  • Supabase (Auth, Postgres, Storage)
  • Zod para validacion
  • Power BI embebido + geoportal externo + n8n opcional
Componentes
  • Rutas web: src/app/*
  • APIs: acceso y signed URLs
  • Middleware admin: src/middleware.ts
  • DB para usuarios, documentos y solicitudes
  • Buckets privados: internos y sensibles

4) Modulos MVP

  1. Inicio (/)
  2. Biblioteca (/biblioteca)
  3. Gobierno propio (/gobierno-propio)
  4. MJN (/mujeres-juventudes-ninez)
  5. Estadisticas (/estadisticas)
  6. SCITA (/scita)
  7. Geoportal interno (/geoportal)
  8. Admin (/admin/*)

5) Seguridad territorial digital

Roles

  • public: contenido abierto
  • internal: contenido interno autenticado
  • admin: gestion y aprobaciones

Visibilidad

  • public: sin login
  • internal: requiere sesion
  • sensitive: no expuesto en frontend publico

6) Flujo de acceso documental

  1. Solicitud en /solicitar-acceso/[instrumento].
  2. Persistencia en public.access_requests.
  3. Revision admin en /admin/solicitudes.
  4. Aprobacion/rechazo por server actions.
  5. Entrega controlada por signed URL temporal.

7) Operacion e infraestructura

Variables de entorno clave

  • NEXT_PUBLIC_SUPABASE_URL
  • NEXT_PUBLIC_SUPABASE_PUBLISHABLE_DEFAULT_KEY
  • SUPABASE_SERVICE_ROLE_KEY
  • NEXT_PUBLIC_APP_URL
  • N8N_EMAIL_WEBHOOK_URL (opcional)

Buckets privados

  • docs-internal
  • docs-sensitive

Comandos operativos

  • npm run sync:plan-instrumentos-storage
  • npm run sync:plan-instrumentos-storage:verify
  • npm run sync:plan-instrumentos-storage:verify-db
  • npm run verify:plan-instrumentos-auth-e2e
  • npm run verify:plan-instrumentos-admin-actions-e2e

8) MVP vs Fase 2

MVP
  • Portal modular por estado
  • Visibilidad por nivel
  • Power BI por embed URL
  • Acceso geoportal por rol
  • CRUD base documental
Fase 2
  • Taxonomias profundas
  • Flujo editorial completo
  • Modulo ACC extendido
  • Incidencia politica ampliada
  • Auditoria y versionado
